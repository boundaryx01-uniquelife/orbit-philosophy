## 선택 또는 판단

Genesis 문서 세트 v1.0의 포함 범위, 개별 문서 버전과 세트 버전의 관계, Git 체크포인트 방식을 결정한다.

## 공통 목표

승인된 핵심 문서와 그 운영·근거 기록을 하나의 안정된 체크포인트로 묶되, 현재 문서와 작업 이력의 권위 차이 및 남은 불확실성을 숨기지 않는다.

## 선택지와 근거

| 선택지 | 기대 효과 | 비용·위험 | 근거 종류 | 근거 |
|---|---|---|---|---|
| 1. 핵심 문서만 v1.0으로 묶음 | 구성이 단순하고 외부 독자가 읽기 쉬움 | 선택과 교정의 근거 및 재개 경로가 세트 밖으로 밀림 | `INFERENCE`, `CONSTRAINT` | ORBIT는 결과뿐 아니라 판단이 만들어진 과정을 보존함 |
| 2. 저장소 전체를 같은 권위의 v1.0으로 취급 | 포함 범위가 명확하고 누락이 적음 | Draft와 과거 Review가 승인 문서와 같은 현재 입장으로 오해될 수 있음 | `FACT`, `INFERENCE` | 저장소에는 현재 문서와 역사 기록이 함께 존재함 |
| 3. 핵심·운영·근거 이력의 3계층 세트 | 읽기, 재개와 근거 추적을 모두 보존하면서 문서별 권위를 구분 | 계층과 버전 관계를 별도 명세해야 함 | `FACT`, `PREFERENCE`, `INFERENCE` | README와 전체 교차검토가 이미 문서 역할을 구분하고 있음 |

## 현재 선택

- 선택: **3. 핵심·운영·근거 이력의 3계층으로 v1.0을 구성한다.**
- 버전 방식: 개별 문서 버전은 유지하고, 검증된 구성 전체에 `Genesis Document Set v1.0`을 부여한다.
- Git 방식: 릴리스 커밋에 주석 태그 `genesis-v1.0`을 부여해 당시 상태를 고정한다.
- 선택한 이유: 사용자가 제안받은 3계층 구성으로 v1.0 확정을 진행하도록 승인했다.
- 선택하지 않은 주요 대안과 이유:
  - 핵심 문서만 묶으면 ORBIT가 중요하게 여기는 선택의 근거와 재개 가능성이 약해진다.
  - 저장소 전체를 같은 권위로 취급하면 현재 입장과 집필 이력을 구분할 수 없다.

## 검증 결과

- 확인된 사실: 7단계 전체 교차검토에서 핵심 문서의 역할, 근거 연결과 저장소 구조가 검증됐다.
- 충족된 조건: 핵심 5개, 운영 2개, 근거·이력 5개 위치를 구분하고 각 역할을 명시했다.
- 남은 불확실성: 외부 독자의 이해도와 장기 기록 부담은 실제 사용 검증이 필요하다.
- 미해결 위험: 세트 구성이나 핵심 문서가 바뀌면 새 세트 버전과 태그가 필요하다.
