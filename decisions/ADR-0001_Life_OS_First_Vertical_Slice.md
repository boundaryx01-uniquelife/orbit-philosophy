# ADR-0001 — Life OS 첫 세로 흐름의 기술 선택

> 상태: 로컬 첫 흐름 구현 결정 / 실제 서비스 운영 방식은 미결정
> 작성: 2026-10-09
> 범위: [이슈 #1](https://github.com/boundaryx01-uniquelife/orbit-philosophy/issues/1)의 첫 제품. 배포 또는 실자료 처리 승인 아님.

## 맥락

질문만으로 시작하고, 출처와 시점을 가진 근거, 관찰과 추론, 모르는 점, 조심스러운 제안 하나, 의사 표현·실행·체감의 분리된 피드백을 같은 계정의 여러 화면에서 이어 봐야 한다. 다른 계정의 자료는 읽거나 바꿀 수 없어야 한다. 공개 저장소에는 합성 사례만 둔다.

## 초기 선택

- **반응형 웹 한 벌**을 먼저 만든다. 휴대폰에서는 질문 입력과 한 장의 제안 카드를 세로로, 태블릿과 PC에서는 같은 내용을 넓은 읽기 폭과 보조 근거 영역으로 배치한다. 세 화면 폭에서 시작·제안·이전 이야기의 입력과 읽기를 검증한다.
- **첫 실행 가능한 흐름은 Python 표준 라이브러리 서버와 SQLite**로 만든다. 서버 세션과 소유자별 조회·변경 검사를 두고, 브라우저 저장소를 원본 데이터나 계정 분리 수단으로 사용하지 않는다. Next.js·Supabase Auth/Database는 운영 자원을 갖춘 뒤 재검토할 대안이다.
- Case, Evidence, Claim, Preference/Constraint, Proposal, Feedback, Chronicle을 분리한다. Evidence에는 출처와 시점, Claim에는 관찰/추론 구분과 불확실성, Feedback에는 제안에 대한 의사 표현·실행 여부·뒤의 체감 결과를 별도 필드/사건으로 둔다. “고려해 볼게”는 실행이나 효과로 승격하지 않는다.
- 저장 성공을 확인한 뒤 화면에 반영하고, 저장 오류를 보이며 재시도할 수 있게 한다. 재접속 시 서버 기록을 다시 읽는다. 수정·삭제 후 다른 세션의 재조회 결과까지 검증한다. 실시간 구독은 첫 흐름의 필수 조건으로 두지 않고, 필요성이 확인되면 추가한다.
- 첫 흐름의 판단 문구는 **합성 fixture와 결정적인 규칙**으로 만든다. 외부 AI 호출은 이 단계에서 사용하지 않는다. 나중에 도입한다면 비밀 값은 서버에서만 다루고, 모델 출력은 출처와 불확실성이 표시된 제안으로 저장한다.

## 이유와 대안

반응형 웹은 세 기기에서 같은 사례를 검증할 수 있다. 외부 프로젝트가 없는 상태에서도 서버의 계정·세션·SQLite로 두 브라우저 세션의 동기화와 계정 분리를 검증할 수 있다. 브라우저 로컬 저장만으로는 이슈의 다기기 기준을 충족하지 못한다. 관리형 인증·DB와 외부 AI 호출은 운영 환경이 정해질 때 다시 판단한다.

## 보호 경계와 검증 관문

- 공개 Git 기록, fixture, 로그, 이슈와 PR에는 실제 건강 자료, 원본 스크린샷, 식별 정보, 인증 정보를 넣지 않는다. 입력 데이터가 필요한 검증에는 합성 사례만 사용한다.
- 인증이 필요한 모든 읽기·쓰기·삭제에 소유자 기준 접근 제어를 적용한다. 다른 계정 접근 실패, 두 세션의 수정·삭제 전파, 저장 실패 뒤 복구를 자동 또는 재현 가능한 검증으로 확인한다.
- 로컬 실험에서는 선택적 첨부 저장과 계정별 내려받기·삭제를 합성 텍스트 파일로 검증한다. 실자료 저장·공개 운영은 보관·삭제·접근 정책을 확정하기 전 열지 않는다.
- 로컬 서버는 기본적으로 루프백에만 바인딩한다. 외부 주소로 열 때는 HTTPS Origin을 요구한다. 공개 운영, 계정 복구, 백업 및 실자료 사용은 별도 검토한다. Supabase를 도입하면 최신 문서와 RLS·권한·소유자 검증을 먼저 확인한다.

## 재검토 조건

실제 사용 흐름에서 첫 질문이 자료 첨부 없이는 성립하지 않거나, 세 기기·두 계정 검증을 현재 구성으로 안정적으로 통과하지 못하면 화면 및 저장 방식을 다시 선택한다.

## 구현 확인

[로컬 실행 문서](../tracks/product/life_os/README.md)의 합성 데이터 API와 브라우저 검증으로 첫 화면, 두 계정·두 세션, 수정·삭제, 세 화면 폭을 확인했다. 이 선택은 실제 건강 자료를 처리하거나 공개 서비스에 배포한다는 결정이 아니다.
