# ADR-0001 — Life OS 첫 화면은 로그인 없는 챗으로 확인한다

> 상태: 사용자 교정 반영 / 2026-10-09
> 범위: [이슈 #1](https://github.com/boundaryx01-uniquelife/orbit-philosophy/issues/1)의 첫 경험을 검증하는 합성 시제품. 실제 서비스 기술 결정 아님.

## 맥락

이슈는 질문 우선 시작, 근거와 불확실성, 제안 하나, 분리된 반응, 이후 재사용을 요구한다. 그러나 처음 구현은 이를 여러 입력 양식과 로그인 화면으로 펼쳐, [CR-0030](CR-0030_Withdraw_Input_Form_Prototype.md)에서 철회한 제품 경험을 다시 만들었다. 사용자는 **메인은 챗이고, 완성되기 전까지 로그인은 만들지 않는다**고 교정했다. [CR-0031](CR-0031_Keep_Life_OS_Chat_First_Without_Login.md)에 오류를 기록한다.

## 현재 선택

- 반응형 **단일 챗 화면**에서 한 입력창으로 질문과 후속 이야기를 받는다. Evidence·Claim·Constraint를 채우는 별도 설문 단계를 두지 않는다. 대화 안에서 현재 관찰, 모르는 점, 질문/제안 하나와 그 이유를 보여 준다.
- 두 공개 **합성 사례**로 자료 없는 시작과 측정 조건이 다른 기록 비교를 검증한다. 답변은 규칙 기반 시제품이라고 표시한다. 모델이 실제 자료를 해석하거나 의학적 원인을 판단한다고 표현하지 않는다.
- 반응 버튼의 의사 표현과 실제 실행·체감을 분리한다. “고려해 볼게”는 실행이나 효과가 아니다. 이전 반응은 같은 대화의 다음 질문에만 참고한다.
- 정적 HTML/CSS/JavaScript와 로컬 Python 정적 파일 서버를 사용한다. 입력은 **탭 메모리만** 사용한다. 로그인, 쿠키, DB, 서버 쓰기 API, 외부 AI 호출, 파일 업로드와 비밀 값은 없다.

## 대안과 이유

앞서 기록한 Next.js·Supabase 또는 Python·SQLite 계정 서버 선택은 **이번 챗 검증 범위에서 철회**한다. 계정과 저장 구조가 대화 경험보다 앞서며, 실제 자료 취급 준비가 없는 상태에서 로그인과 업로드를 노출했다. 정적 시제품은 우선 사용자가 원하는 대화의 형태를 확인할 수 있고 공개 저장소에 합성 자료만 둔다.

## 현재 한계와 다음 결정

새로고침하면 대화가 사라지고 기기 간 동기화·계정 분리도 없다. 이슈의 그 수용 기준은 최신 사용자 지시에 따라 **챗 경험 확인 이후**로 미룬다. 파일 첨부와 실제 AI 해석도 제공하지 않는다. 챗 흐름이 사용자 의도에 맞는지 확인된 뒤 자료 보관·삭제·계정·동기화·모델 호출 경계를 설계한다. 실제 건강 자료 사용과 공개 배포는 별도 판단이다.
