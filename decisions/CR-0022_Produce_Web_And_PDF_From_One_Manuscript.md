# Choice Record — CR-0022

> Status: `DECIDED`
> Date: 2026-09-29
> Issue originator: EPUB v0.1 이후 사용자의 웹·PDF 판본 요청
> Final decision owner: 사용자

## 선택 또는 판단

EPUB 시제품에 이어 일반 웹판과 PDF판 중 하나만 만들지, 두 형식을 모두 만들지, 그리고 원고를 어떻게 관리할지 결정한다.

## 선택지와 근거

| 선택지 | 기대 효과 | 비용·위험 | 근거 종류 | 근거 |
|---|---|---|---|---|
| 1. EPUB만 유지 | 관리할 산출물이 가장 적음 | 브라우저 즉시 접근과 고정 지면 검토를 할 수 없음 | `CONSTRAINT` | EPUB은 전자책 읽기에 최적화됨 |
| 2. 웹 또는 PDF 중 하나만 추가 | 특정 용도의 검증을 빠르게 시작 | 다른 읽기 환경의 문제를 늦게 발견 | `INFERENCE` | 웹과 PDF는 서로 다른 사용 상황을 해결함 |
| 3. 공통 원고에서 웹과 PDF를 모두 생성 | 전자책·브라우저·고정 지면을 비교하면서 내용 불일치를 줄임 | 빌드와 검증 절차가 세 종류로 늘어남 | `PREFERENCE`, `CONSTRAINT`, `INFERENCE` | 사용자가 일반 웹판과 PDF판도 요청함 |

## 현재 선택

- 선택: **공통 원고에서 반응형 웹북과 A5 PDF를 모두 만든다.**
- 선택한 이유: 사용자가 EPUB 이후 두 형식의 추가 가능성을 물었고, 각각 즉시 접근과 고정 지면이라는 구별되는 가치가 있다.
- 범위 제한: 현재 전체 구성과 제1장만 담은 `v0.1` 시제품으로 유지한다.
- 원고 관리: 내용은 기존 마크다운에 두고, 웹·EPUB·PDF 빌드는 표현과 검증만 담당한다.

## 검증 결과

- 웹은 글꼴과 두 이미지를 포함한 단일 HTML로 만들어 외부 네트워크 없이 열 수 있다.
- PDF는 A5 8쪽으로 생성되며 한글 글꼴, 책갈피, 쪽 번호와 메타데이터를 포함한다.
- PDF 전 페이지 렌더링에서 잘린 글자, 겹침, 깨진 한글과 이미지 오류가 발견되지 않았다.
- 남은 불확실성: 실제 휴대전화 브라우저, 전자책 앱과 종이 출력에서의 사용자 반응은 아직 없다.

## 남아 있는 차이

없음. 공개 웹 배포와 출판 인쇄 규격 적용은 별도 결정으로 남긴다.

## 최종 판단

- 판단자: 사용자
- 결정: `웹 + PDF 추가, 공통 원고 유지`
- 판단 근거: 사용자가 두 판본을 요청했고, 동일 내용을 따로 편집하지 않도록 단일 원고 빌드가 필요함.

## 다시 검토할 조건

- 세 빌드의 유지 비용이 실제 검증 가치보다 커질 때
- 웹판을 공개 URL로 배포할 때
- 인쇄소 제출용 PDF 규격이 정해질 때
- 전체 원고에서 매체별로 내용 자체를 달리해야 할 근거가 생길 때
