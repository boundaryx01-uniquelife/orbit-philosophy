# 다시 펼쳐 보는 작업 안내 {.unnumbered}

이 페이지는 본문의 방법을 다시 찾기 위한 안내다. 모든 칸을 매번 채우거나 모든 질문에 답할 필요는 없다. 지금 판단에 필요한 것만 사용한다.

| 언제 | 무엇을 확인하거나 남기는가 | 본문 |
|---|---|---|
| 작업을 시작하거나 방향이 어긋났을 때 | 해결할 문제 / 중요 기준 / 하지 않을 것 / 완료 조건. 모르는 조건은 미확인으로 남긴다. | 제4장 |
| 중요한 선택을 할 때 | 선택 / 이유 / 중요한 대안 / 불확실성 / 재검토 조건 | 제7장 |
| 작업을 멈추거나 다시 시작할 때 | 목표 / 완료한 것 / 확정한 선택 / 남은 차이와 위험 / 미결정 사항 / 다음 시작점 | 제9장 |

결과를 받은 뒤에는 뜻이 맞는지와 사실·계산·작동이 맞는지를 따로 살핀다. 현재 단계를 닫을 때는 처음의 문제, 완료 조건, 남은 한계, 다시 열 조건을 확인한다. 기록의 크기와 확인의 깊이는 선택의 무게에 맞춘다.

## 이 글에서 사용하는 말 {.unnumbered}

아래 설명은 본문을 찾아보기 위한 요약이다. 일반적인 사전이나 모든 AI 작업에 적용할 표준 정의는 아니다. 전문 용어의 통용 뜻과 이 글에서 정한 표현의 범위를 구분해 적었다.

| 표현 | 이 글에서의 뜻 | 설명을 찾을 곳 |
|---|---|---|
| ORBIT Philosophy | 한 사용자와 대화형 AI의 협업 대화와 기록을 묶은 프로젝트명. 널리 통용되는 협업 이론의 이름은 아니다. | 서문 |
| LLM | Large Language Model, 대규모 언어 모델. 많은 언어 자료에서 배운 패턴을 바탕으로 글을 처리하고 생성하는 AI 모델이다. 대화형 AI를 만드는 데 쓰이지만, 모델 자체와 이를 사용하는 서비스는 구분한다. | 서문 |
| 대화형 AI / AI | 이 글에서는 ChatGPT처럼 대화하며 작업하는 AI를 가리킨다. 모든 AI가 LLM이거나 대화형 AI라는 뜻은 아니다. 이후 본문에서는 문맥에 따라 두 표현을 사용한다. | 서문 |
| 프롬프트 | AI에게 건네는 질문이나 작업 요청 | 서문 |
| 첫 결과물 | AI의 첫 응답부터 초기 대화를 거쳐 처음 형태를 갖춘 문서·코드·디자인·계획까지 가리키는 넓은 표현. 모두 시험을 목적으로 만든 것은 아니다. | 제1장 |
| 시험용 첫 결과물(MVP) | MVP는 Minimum Viable Product의 줄임말로, 제품 개발에서 실제 반응을 통해 배울 수 있는 초기 형태를 뜻한다. 이 글에서는 문서·코드·디자인·계획에서도 핵심 생각을 시험하고 배우기 위한 첫 형태를 ‘시험용 첫 결과물’이라고 부른다. 모든 초안이나 첫 응답과 같은 뜻은 아니다. | 제1장 |
| 인스턴트적 사고 | 형태가 나왔으니 판단도 끝났다고 여기는 태도. 이 대화에서 뜻을 정리한 표현이다. | 제1장 |
| 경계 | 이번 작업에서 하지 않을 일과 넘지 않을 범위 | 제1장 |
| 완료 조건 | 지금 단계를 마쳤다고 판단할 수 있는 구체적인 기준. 결과물에 담겼는지와 실제로 전달되거나 작동했는지는 확인 시점이 다를 수 있다. | 제1·4장 |
| 추론 | 주어진 말·맥락·근거에서 아직 직접 확인하지 않은 뜻이나 판단을 이끌어내는 일. 제3장에서는 요청의 뜻을 짐작하는 데, 제7장에서는 선택의 근거를 구분하는 데 쓴다. | 제3·7장 |
| 되말하기 | 이해한 뜻을 자기 말로 설명해 상대가 어긋난 부분을 고칠 수 있게 하는 일. 원문을 그대로 반복하거나 그 설명의 사실성을 보증하는 일은 아니다. | 제3장 |
| 대화 깔때기 | 가능성을 펼친 뒤 목적에 맞지 않는 것을 덜어내는 대화 과정. 새 조건이 드러나면 다시 넓힐 수 있다. 이 대화에서 정리한 비유다. | 제4장 |
| 통역 | 경험과 우선순위를 작업 기준으로, AI의 제안을 판단할 수 있는 말로 바꾸는 일. 여기서는 서로 다른 언어를 번역한다는 뜻으로 쓰지 않는다. | 제4장 |
| 의미 확인 | 서로가 이해한 요청의 뜻을 설명하고, 맞거나 어긋난 부분을 확인하는 일. 같은 의견을 갖거나 사실이 맞음을 입증하는 것과는 다르다. | 제3·4장 |
| 검증 | 결과를 목적·기준·확인 가능한 근거에 비춰 살피는 일. 사실·계산·작동, 논리와 위험 등을 확인한다. 뜻을 맞추었다고 이러한 확인까지 끝난 것은 아니다. | 제1·4·6장 |
| 오해 / 차이 | 상대의 뜻을 다르게 이해한 상태 / 뜻을 이해한 뒤에도 남을 수 있는 판단이나 우선순위의 차이 | 제5장 |
| 결정 / 합의 | 현재 무엇을 할지 정하는 일 / 서로 무엇을 받아들였는지 확인하는 일. 결정했다고 모든 반론이 사라지거나 합의가 이루어진 것은 아니다. | 제5장 |
| 문제 제기자 / 판단권 | 무엇이 불편하고 왜 작업을 시작했는지 밝힌 사람 / 그 문제가 충분히 해결되었는지 판단할 권한. 만족한다고 오류가 없어지거나 타인에게 영향을 주는 실행 권한까지 생기는 것은 아니다. | 제6장 |
| 파트너 / AI의 책임 | 해석과 반론을 성실하게 다루는 협업 방식 / 그 협업에서 AI의 응답과 행동에 요구하는 기준. 인간과 같은 권리나 현실적 책임을 부여한다는 뜻은 아니다. | 제6장 |
| 관계의 기억 | 확인한 뜻과 경계, 선택과 교정을 다음 판단에 사용할 수 있게 외부에 남긴 기록. AI의 자동 메모리 기능과 달리, 직접 관리하고 다시 확인할 수 있는 기록을 강조한다. | 제8장 |
| 변화 기록(Chronicle) | 어떤 오해나 새 정보 때문에 생각이 바뀌었는지 남기는 기록. Chronicle은 ORBIT에서 사용하는 내부 명칭이다. | 제9장 |
| 선택 기록(Choice Record) | 무엇을 왜 선택했고 어떤 대안·불확실성·재검토 조건이 남았는지 적는 기록. 제7장에서 방법을 설명하고 제9장에서 ORBIT 내부 명칭을 소개한다. | 제7·9장 |
| 완성 / 완료 / 완결 | 완성은 목적에 맞게 결과물을 다 만든 상태, 완료는 작업이나 단계가 끝난 상태를 가리킬 수 있다. 이 글의 ‘완결’은 남은 한계와 재검토 조건을 밝히고 판단과 기록까지 마무리해 현재 단계를 닫는 일을 강조한다. 세 말의 사전적 뜻을 새로 정하거나 엄격한 단계로 나누는 구분은 아니다. | 제1·10장 |
| 버전 | 수정 전후의 상태를 구분한 판본. 번호만으로 품질이나 완벽함이 보장되지는 않으며, 확인한 것과 남은 것을 함께 밝혀야 한다. | 제10장 |
| PDF | 화면 배치를 고정해 보여 주는 문서 형식. 제7장에서는 웹판을 먼저 만들기로 한 선택을 설명하는 데 등장한다. | 제7장 |
