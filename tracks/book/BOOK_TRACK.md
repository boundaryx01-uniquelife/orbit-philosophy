# ORBIT Book Track

> Version: FIRST AUTHORING SET v1.0
> Status: CONTENT FROZEN / TERMINOLOGY COMPLETE v1.1
> Source baseline: `Genesis Document Set v1.0`

## 이 트랙이 만드는 것

책 트랙은 ORBIT의 문서를 그대로 묶어 출판하는 작업이 아니다. 독자가 인간–LLM 협업에서 겪는 어긋남을 자신의 경험으로 알아차리고, 첫 결과물 이후에 무엇을 확인하고 기록할지 따라갈 수 있는 서사와 실천 구조를 만든다.

## 독자 가설

첫 독자는 LLM을 이미 사용하지만 다음과 같은 불편을 겪는 초보·중간 사용자다.

- 결과는 빠르고 매끄럽지만 자신의 뜻과 조금씩 어긋난다.
- 더 좋은 답을 받으려다 정보와 선택지가 늘어나 방향을 잃는다.
- 프롬프트 기술은 배우지만 결과를 판단하는 기준은 선명해지지 않는다.
- 대화에서 바로잡은 내용이 다음 작업에서 사라진다.

## 독자에게 약속하는 변화

이 책을 읽은 독자는 ‘좋은 프롬프트 한 번’을 찾는 대신 다음을 할 수 있어야 한다.

1. 첫 결과물을 완성이 아닌 의미 확인과 검증의 시작점으로 본다.
2. 목표·경계·완료 조건을 LLM과 서로 설명하고 교정한다.
3. 동의와 차이, 선택한 이유와 버린 대안을 함께 남긴다.
4. 이전 대화의 교정을 다음 판단에 다시 사용한다.

## 이 책이 아닌 것

- 프롬프트 예시를 모은 활용서
- LLM을 인간과 같은 존재로 선언하는 책
- 인간의 최종 판단권만 강조하는 통제 안내서
- ORBIT의 내부 기록을 시간순으로 모두 옮긴 회고록
- 검증되지 않은 성공 사례를 붙인 자기계발서

## 작업 제목

**《첫 결과물이 곧 완성은 아니다》**

부제: 첫 프롬프트와 시험용 첫 결과물 이후, 인간과 AI가 함께 완성해 가는 법

‘첫 결과물’은 첫 응답 하나만을 뜻하지 않는다. 첫 프롬프트에서 시작해 초기 대화를 거쳐 처음으로 형태를 갖춘 문서·코드·디자인·계획·MVP를 함께 가리킨다. 제목과 부제는 전체 초안의 독자 교정 뒤에 다시 판단한다.

## 3부 구성안

### 1부. 완성처럼 보이는 첫 결과물

1. **완성처럼 보이는 첫 결과물** — 첫 프롬프트, 첫 구현과 MVP
2. **친절한 답이 목표를 잃게 할 때** — 과잉 친절과 방향 이탈
3. **같은 말을 해도 같은 뜻은 아니다** — 의미 전달의 착각

### 2부. 대화를 판단의 과정으로 바꾸기

4. **결과를 만들기 전에 네 줄로 확인하기** — 목표·경계·완료 조건 되말하기
5. **다름을 지우지 않는 관계** — 동의보다 정확한 차이
6. **판단권과 파트너의 책임** — 결정권과 반론의 공존
7. **선택에는 이유가 따라야 한다** — 사실·제약·선호·경험·추론

### 3부. 다음 판단을 처음부터 시작하지 않기

8. **대화가 사라지면 관계도 처음으로 돌아간다** — 관계의 기억
9. **오해와 교정의 궤적을 남기는 법** — Chronicle과 Choice Record
10. **완성하지 않고도 완결할 수 있는가** — 버전, 재검토와 동행

## 한 장의 기본 구조

모든 장은 같은 내용 형식이 아니라 같은 검증 구조를 따른다.

1. 실제 어긋남이 드러나는 장면
2. 그 장면을 잘못 해석하기 쉬운 방식
3. ORBIT가 확인한 원칙
4. 독자가 자기 대화에 적용할 짧은 실천
5. 선택과 반론을 남기는 기록 질문
6. 원자료와 해석의 경계 표시

## 전체 원고 초안

현재 전체 원고는 서문과 열 장, 작업 안내를 함께 다듬은 [1차 저작 완성본 v1.0](BOOK_FIRST_AUTHORING_SET_v1.0.md)이다. 제1~3장은 첫 결과물·과잉 친절·의미의 어긋남을 다룬다. [제4장](drafts/Chapter_04_Check_Four_Lines_Before_Creating_v0.3.md)은 실제 설명회 준비 조건에서 재구성한 사례로 확인과 교정을 보여 준다. 제5~7장은 차이·판단권·선택을, 제8~10장은 기록과 완결을 다룬다. v1.0은 1차 저작의 승인 기준점이며, 출간·유통·최종 조판까지 마쳤다는 뜻은 아니다. 이후 변경은 [2단계 용어 체계화](TERMINOLOGY_SYSTEMATIZATION.md)의 근거와 함께 남긴다.

전체 초안의 검증 질문은 다음과 같다.

- 독자가 첫 결과물과 완성을 구분할 수 있는가?
- ‘빠른 생성이 나쁘다’는 주장으로 오해하지 않는가?
- 읽은 뒤 자신의 최근 LLM 작업을 한 번 더 검토하고 싶어지는가?
- 실천 질문이 철학의 여운을 깨뜨릴 만큼 설명서처럼 느껴지지 않는가?
- 열 장이 첫 결과물의 발견 → 대화와 판단 → 기록과 완결의 흐름으로 자연스럽게 이어지는가?
- `완성·완료·완결`, `확인·검증`, `AI·LLM` 같은 인접 표현을 초보 독자가 구분할 수 있는가?

## EPUB 시제품

책 트랙을 먼저 진행한다는 사용자의 선택에 따라, 3부 10장 원고를 [EPUB v1.1](epub/dist/First_Output_Is_Not_Completion_v1.1.epub)으로 묶었다. 이 판본은 1차 저작의 완료 상태를 보존하며, 전자책 환경에서 가독성과 목차 흐름을 계속 확인하는 기준본이다.

- 제작 원칙과 남은 결정: [`EPUB_PRODUCTION.md`](EPUB_PRODUCTION.md)
- 다시 만드는 방법: [`epub/README.md`](epub/README.md)
- 표지와 삽화의 의미·생성 지시: [`assets/README.md`](assets/README.md)

표지는 두 궤도의 정렬을 상징으로 사용하고, 제1장 삽화는 완성된 외형과 아직 맞지 않은 목표의 차이를 보여 준다. 후속 삽화는 원고보다 먼저 만들지 않는다.

형식별 파일을 따로 집필하지 않고 열 장의 마크다운을 공통 원고로 유지한다. 현재 운용 우선순위와 PDF 재개 조건은 [`FORMAT_MATRIX.md`](FORMAT_MATRIX.md)에 정리한다.

웹 교정본은 저장소 원고를 자동으로 덮어쓰지 않는다. 현재 브라우저에 자동 저장한 뒤 Markdown으로 내보내며, 실제 원고 반영은 [`CR-0023`](../../decisions/CR-0023_Keep_Web_Corrections_Local_Until_Reviewed.md)에 따라 별도로 판단한다.

## 제작 흐름

1. 장별 중심 질문을 하나로 제한한다.
2. Chronicle에서 사건과 직접 인용의 범위를 정한다.
3. Genesis·WHY·Philosophy에서 해석과 원칙을 가져온다.
4. 장면 → 해석 → 실천의 초안을 쓴다.
5. 원자료보다 더 극적인 감정이나 성공을 추가하지 않았는지 검토한다.
6. 독자 반응을 받아 이해·공감·행동 변화와 거부 지점을 기록한다.
7. 다음 장으로 진행하거나 구조를 수정한다.

## 첫 검증 계획

- 대상: LLM 사용 경험이 서로 다른 독자 3~5명
- 자료: 3부 10장 전체 초안과 독자 기록 질문
- 확인: 핵심 메시지 회상, 막히는 용어, 반복·지루한 지점, 자신의 경험 연결, 실제 행동 의향
- 통과 기준: 과반수가 ‘속도가 아니라 완성처럼 보이는 첫 결과물에서 판단을 멈추는 태도에 대한 경고’라고 자기 말로 설명하고, 최소 한 가지 재검토 행동을 제시함

## 아직 결정하지 않은 것

- 실제 출판·유통 여부
- 최종 제목·분량·독자 연령
- 공동 저자 표기와 인간–LLM 대화의 인용 형식
- 실습 워크북을 본문에 넣을지 별책으로 분리할지

이 결정은 샘플 독자 검증 뒤에 내린다.
