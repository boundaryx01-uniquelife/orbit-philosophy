# 제품 흐름 1차 시험 안내

> 상태: 실제 사용 전 / 3회 관찰 대기
> 자료: [클릭 시험본](index.html)
> 근거: 제품 명세 v0.1, 책 제1·4·6·7·9·10장, CR-0030

## 무엇을 확인할까

**가벼운 작업에서 작은 결과를 먼저 보는 경로**와 **중요한 작업에서 뜻을 먼저 확인하는 경로**가 모두 어긋남을 발견하고 다음 작업에 필요한 기록을 남기는지 시험한다. 두 경로가 항상 같은 효과를 낸다고 전제하지 않는다.

이 파일은 로컬에서 여는 단일 HTML이다. AI 자동 연결, 서버 저장, 계정은 없다. 입력은 새로고침하면 사라지므로 기록이 필요하면 마지막 화면에서 Markdown을 내려받는다. 실제 개인정보나 민감한 내용은 넣지 않는다.

## 실제 작업 3회

문서, 교육, 개발 중 서로 다른 실제 작업 3개를 사용한다. 하나의 과제를 3명이 진행하거나 한 사람이 서로 다른 3개 과제를 진행해도 된다. **적어도 한 번은 각 시작 경로를 사용**하고, 경로를 고른 이유를 먼저 말한다. 임의로 예쁜 답을 만들어 넣지 말고 실제 AI 응답이나 실제 초안을 붙여넣는다. AI를 쓰지 않은 단계는 미확인으로 둔다.

1. 시작: 문제, 알고 있는 기준·경계·완료 조건을 적는다. 빈칸을 채우기 위해 답을 꾸미지 않는다.
2. 경로 선택: 결과를 다시 만들 비용과 현재 조건의 중요도를 말한 뒤 ‘먼저 뜻 확인’ 또는 ‘작은 결과 먼저’를 고른다.
3. 답 확인: AI가 이해한 점과 어긋난 점, 결과를 보고 처음 알게 된 기준을 기록한다. 사실·작동 검증이 필요한지도 따로 적는다.
4. 선택: 이유와 근거 종류, 중요한 다른 안, 남은 차이·위험, 다시 열 조건을 적는다.
5. 재개: Markdown을 내려받고 페이지를 닫는다. 나중에 **그 파일만** 읽어 다음 행동을 말할 수 있는지 확인한다. 시험본에는 파일 다시 불러오기 기능이 없다.

## 3회 뒤 판단

기존 명세의 ‘10분 안에 첫 재개 기록’ 기준을 시간과 작업 난도로 함께 살핀다. 세 회차 중 하나라도 단계를 거치기 위해 사실을 꾸며 넣거나 중요한 반론·위험이 사라졌다면 수정 사항으로 기록한다. 모든 일을 다섯 단계로 입력해야만 한다고 강요하는지, 작은 결과를 먼저 보는 길이 실제로 도움이 되는지도 확인한다. 관찰 없이 성공·실패를 적지 않는다.

그 뒤 [공통 검증 기록](../../../templates/Expansion_Validation_Record.md)으로 계속·수정·보류를 결정한다. 흐름을 검증하기 전에는 기술 스택·LLM 연결 방식이나 정식 제품 기능을 확정하지 않는다.

## 시험본의 현재 범위

네 화면의 이동, 두 시작 경로, AI 응답 붙여넣기, 교정과 근거 기록, 재개용 Markdown 내려받기를 시험한다. 입력은 메모리에만 있고 항목별 확인·교정 이력·JSON 왕복·다중 작업 보관·AI 호출·사실 검증은 구현되지 않았다. 이 기능들은 정식 MVP 명세의 수용 기준으로 남아 있으며, 시험본이 그 기준을 충족했다고 판단하지 않는다.
