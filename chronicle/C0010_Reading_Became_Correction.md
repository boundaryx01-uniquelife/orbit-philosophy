# C0010 — Reading Became Correction

> Status: EXPERIMENT v0.1
> Date: 2026-09-29
> Trigger: 사용자가 웹판을 읽으며 표현을 바로 교정하고 싶다고 제안함

## 읽기와 집필 사이의 거리

웹판과 PDF판을 만든 뒤 사용자는 문장을 더 다듬어야 할 부분이 보인다고 했다. 파일을 내려받아 별도 편집기로 옮기는 대신, 읽는 화면에서 바로 고칠 수 있는 페이지를 만들 수 있는지 물었다.

이 요청은 독자 검증과 집필을 분리된 단계로만 보던 흐름을 바꾸었다. 읽다가 어색함을 발견한 바로 그 자리에서 문장을 고칠 수 있다면, 기억에 의존해 나중에 위치를 다시 찾는 손실을 줄일 수 있다.

## 바로 고치되 바로 덮어쓰지 않기

즉시 교정과 즉시 반영은 같은 일이 아니다. 공개 웹 페이지가 저장소 원고를 곧바로 바꾸게 하면, 편리함과 함께 원문 손상·인증·변경 충돌이라는 새로운 위험이 생긴다.

첫 실험에서는 교정 내용을 현재 브라우저에 자동 저장하고 Markdown 파일로 내보내게 했다. 사용자는 읽으며 문장을 직접 고칠 수 있지만, GitHub 원고에 반영하는 판단은 그 파일을 검토한 뒤 별도로 내린다.

이 구조는 완성된 편집 시스템이 아니다. 읽기와 교정이 실제로 가까워지는지, 원문 보호 경계가 지나치게 번거롭지는 않은지 확인하기 위한 첫 결과다.
