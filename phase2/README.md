# 2단계 · 개인화된 생활 판단 에이전트

> 상태: 첫 작동 흐름 개발 중 · 2026-10-06
> 이 폴더는 책·철학 저작물과 분리된 제품 작업 공간이다. 첫 검증 분야는 쇼핑이다.

## 해결하려는 문제

사용자는 사무용품, 일상·먹거리, 전자제품, 차량처럼 분야별 지침과 대화를 나눠 사용해 왔다. 매번 다른 채팅에서 상황을 다시 설명하고, 어느 판단이 왜 바뀌었는지 이어 쓰기 어렵다. 이 앱은 **한 대화 공간에서 관련 분야의 지침을 적용하고, 대화와 자료에서 확인한 맥락을 다음 판단에 연결**한다.

처음부터 사용자의 상태를 다 알 수 없다. 봇은 현재 아는 것으로 먼저 답하고, 판단이 달라질 수 있는 정보가 부족할 때 이유를 설명하며 묻는다. 추천, 사용자의 선택, 실제 구매·실행, 이후 결과를 따로 남긴다. 누적 기록은 실패 가능성을 줄이기 위한 근거이며 효과를 보장하는 성향 판정이 아니다.

## 원자료와 현재 결정

| 자료 | 확인된 점 | 제품 결정 |
|---|---|---|
| 사용자 제공 분야별 지침 문서 | 공통 쇼핑 원칙과 네 분야별 판단 기준이 분리되어 있다. 과거 개인 조건은 달라질 수 있다. | 원문은 비공개 자료로 취급한다. 공개 코드에는 개인 조건·수치·구매 이력을 복제하지 않고, 비식별화한 분야별 검토 원칙만 둔다. |
| [공개 Genesis](../genesis/GENESIS_PUBLIC_TRANSCRIPT.md) | 목적별 쇼핑에서 출발해 증거·상태·제약·판단·행동으로 확장했다. | 이 흐름은 앱 내부 판단 방식이다. 책이나 Chronicle의 문서 형식을 UI에 그대로 옮기지 않는다. |
| 현재 대화에서 확인한 사용자 요구 | 질문과 재질문을 통해 의견을 교환하고 선택하며, 그 과정이 다음 판단의 자료가 된다. 휴대폰·태블릿이 기본 사용 기기다. | 채팅을 기본 화면으로 두고, 관련 근거·기억·결정은 필요할 때 펼쳐 본다. |

첨부 지침의 고정 답변 목차와 점수 매기기는 **과거 운영 방식**으로 보존한다. 현재 제품에서는 긴 정형 답변을 강제하지 않고, 비교 대상과 근거가 충분할 때만 점수를 검토한다. 민감한 과거 조건은 다른 분야에 자동 적용하지 않는다. 비공개 RAW 대화 원문은 이 저장소에 없으므로 그 발화까지 확인했다고 주장하지 않는다.

## 첫 제품 경계

합성 대화로 확인한 [휴대폰 화면](docs/phone-synthetic.png)과 [태블릿 화면](docs/tablet-synthetic.png)을 함께 둔다. 이미지 속 AI 답변은 테스트 서버가 만든 가짜 응답이며 실제 상품 분석 결과가 아니다.

```text
사용자 질문·링크
  → 관련 쇼핑 분야 지침 선택 (사용자가 고칠 수 있음)
  → 해당 대화와 확인된 공통 맥락만 읽기
  → 제공된 자료에서 관찰·추정·미확인을 구분
  → 답변 또는 판단을 바꾸는 질문 하나
  → 사용자 선택·실행·후속 경험을 별도로 저장
  → 다음 대화에서 관련 기록을 출처와 함께 다시 확인
```

네 분야를 메뉴에 억지로 나열하지 않는다. 한 대화에서 시작하고, 현재 적용된 분야를 보여주며 바꿀 수 있게 한다. 다른 대화의 세부 조건은 사용자가 공통 맥락으로 확인한 경우에만 재사용한다. 첫 검증은 전자제품 구매와 다른 쇼핑 분야 한 건을 이어서 시험해 맥락 범위를 확인한다.

기존 `tracks/product/`의 입력 깔때기 가설과 고정 상품 카드 시제품은 이 제품의 구현 기반이 아니다. 첫 버전은 공개 저장소에 합성 자료만 둔다. 실제 상품 페이지 수집, 이미지 해석, 다기기 운영 인증·동기화는 검증과 외부 자원이 필요하며 구현 상태를 [앱 안내](app/README.md)에 구분한다.

교육자료는 지금 설계하지 않는다. 책이 쓰이고 앱이 만들어지는 실제 대화·교정 과정은 나중에 교육자료로 재구성할 수 있도록 필요한 사실만 별도 프로젝트 기록에 남긴다.

## 짧은 기술 결정 · ADR-001

- **화면:** 휴대폰의 대화 입력을 중심으로 한 반응형 웹. 태블릿에는 대화 목록을 옆에 두고, 넓은 화면에서는 맥락 패널도 펼친다. 같은 코드를 세 크기에서 확인한다.
- **대화 생성:** 서버에서만 호출하는 OpenAI 호환 채팅 API. 모델이 없어도 합성 응답을 실제 판단인 것처럼 보여주지 않는다.
- **저장:** 이 단계는 로컬 SQLite와 브라우저별 익명 세션을 쓴다. 원문 대화와 확인된 기억을 분리하고 기억에는 대화·분야·전체 범위를 붙인다. 서버가 소유 범위를 검사한다.
- **운영 전 전환:** 실제 다기기 동기화와 복구에는 계정 인증, 서버 데이터베이스, 백업·삭제 정책, 업로드 보안이 필요하다. 테스트 편의를 위해 현재 로그인 화면은 만들지 않았다. 익명 세션을 운영용 계정 분리나 기기 간 동기화로 간주하지 않는다.
