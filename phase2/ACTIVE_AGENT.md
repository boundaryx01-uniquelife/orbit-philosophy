# 능동형 에이전트 · 첫 검증 설계

## 목적

사용자가 질문할 때만 반응하는 채팅을 넘어서, 대화에서 확인한 관심사와 미해결된 판단을 살펴본 뒤 먼저 말을 걸지 결정한다. 쇼핑은 첫 판단 분야이지만, 알아 가기 위한 대화 자체를 쇼핑에 가두지 않는다. 현재 시각이나 사용자의 행동을 관찰했다고 가장하지 않는다.

## 지금 구현한 판단 고리

1. 사용자가 웹에서 Telegram을 일회용 코드로 연결하고 **먼저 말 걸기**를 별도로 켠다. 연결만으로 능동 발신을 허용하지 않는다.
2. 작업자가 최근 대화와 사용자가 확인한 기억을 읽는다. 12시간 이상 지난 새 사용자 발언이 있고, 최근 3일에 먼저 보낸 메시지가 없으며, 같은 발언을 이미 검토하지 않았을 때만 판단한다. 30일 넘은 발언은 오래된 맥락으로 본다.
3. 모델은 `보냄/침묵`, 질문 하나, 어느 발언을 근거로 왜 묻는지 구조화해 반환한다. 근거가 없거나 모델 연결에 실패하면 발신하지 않는다.
4. 발신 직전 연결·허용·최신 사용자 발언을 다시 확인한다. 전송 후 질문과 판단 이유를 기록한다. 같은 발언에 대해서는 무응답 시 반복하지 않는다. `/pause` 또는 웹의 끄기 버튼이 즉시 발신 허용을 내린다.

이것은 작은 첫 판단 고리다. 질문의 실제 유용성은 모델 출력만으로 증명되지 않는다. 사용자의 답변율, 대화에 도움이 되었는지, 방해로 느꼈는지, 장기적으로 판단이 나아졌는지 확인해야 한다. 빈 안부나 개인정보 수집량 자체를 성공으로 보지 않는다.

## 대화·검색·채널

- 웹과 연결된 Telegram은 같은 대화 저장 함수를 쓴다. Telegram에서 쓴 내용은 웹의 이전 대화에 나타난다.
- 모델과 검색은 서버에서만 호출한다. 검색을 설정하면 최신 가격·후기·비교를 요청하는 문장에서 웹 검색 요약 최대 3개를 가져온다. 제목·요약·URL·확인 시점을 모델에 전달하고 URL은 `검색 요약, 원문 미검증` 근거로 저장한다. 검색 성공은 판매 페이지 본문 확인이나 가격 검증을 뜻하지 않는다.
- Telegram 봇은 사용자가 먼저 `/start`로 연결한 개인 대화에만 답한다. 카카오톡은 별도 플랫폼 검토가 필요하다.

## 다음 검증에서 필요한 것

실제 서비스에는 알림 선호 시간대, 주제별 거절·휴식, 제안별 반응, 중복 발신 방지용 전송 대기열, 계정 복구와 다기기 인증이 필요하다. 현재 실행기는 **한 프로세스**를 전제로 한다. 네트워크 장애 때 Telegram 수신과 저장이 정확히 한 번씩 처리된다는 보장은 아직 없다. 모델이 잘못된 근거를 만들어 질문할 위험도 있으므로 실제 발신 전에 합성 시나리오와 소수의 자발적 시험에서 품질을 봐야 한다.
