# Book Part One v0.3 Cross Review

> Status: `COMPLETE / READY FOR USER CORRECTION`
> Date: 2026-09-30
> Scope: 제1장 v0.2, 제2장 v0.1, 제3장 v0.1과 EPUB·웹·PDF v0.3

## 검토 목적

1부의 세 장이 서로 다른 질문을 맡으면서도 하나의 흐름으로 읽히는지, 실제 기록과 예시의 경계가 분명한지, 추상적인 주장이 독자가 판단할 수 있는 설명으로 이어지는지 확인했다.

## 장별 역할

| 장 | 중심 질문 | 다음 장으로 넘기는 것 |
|---|---|---|
| 1장 | 왜 첫 결과물을 완성으로 오해하는가? | 결과 이후에 목표와 경계를 다시 확인할 필요 |
| 2장 | 왜 유용한 확장이 목표를 흐릴 수 있는가? | 제안과 실행, 일반적 완성도와 목표 적합성의 구분 |
| 3장 | 어떻게 서로 다른 의미를 확인할 것인가? | 되말하기와 네 줄 확인, 2부의 대화 과정 |

## 적용한 수정

1. 제2장의 “더 좋아 보이지만 목표에서는 멀어질 수 있다”에 두 기준의 차이를 직접 설명했다.
2. 핵심 기능 검증용 MVP에 로그인과 통계를 더하는 사례를 붙여, 외형의 완성도와 검증 목적이 어긋나는 과정을 보여 줬다.
3. 제3장의 “간단하게”, “초등학생 수준”은 실제 사건이 아니라 의미 차이를 설명하기 위한 예시로 유지했다.
4. 직접 대화를 다듬은 제2장 인용에는 편집 주를 남겨 원문과 편집 문장의 경계를 표시했다.
5. EPUB·웹·PDF에서 초안용 Version·Status·Sources 머리말이 독자 본문에 노출되지 않도록 빌드 필터를 통일했다.
6. 세 장을 추가한 웹 교정본은 v0.3 저장 키를 사용해 이전 판본의 로컬 교정 내용과 분리했다.

## 반복과 경계 검토

- 제1장의 네 가지 재검토 질문은 이미 나온 결과물을 평가하는 데 사용한다.
- 제3장의 네 줄 확인은 중요한 작업을 시작하거나 다음 수정을 시작하기 전에 공동 기준을 확인하는 데 사용한다.
- 두 형식은 항목 수가 같지만 시점과 역할이 달라 현재는 유지한다. 독자가 같은 목록으로 느낀다면 2부 집필 전에 하나로 합치거나 표현을 달리한다.
- “대화 깔때기와 통역”은 제3장에서 개념만 소개하고, 구체적인 진행 방법은 제4장에 남긴다.

## 제작 검증

- EPUB: ZIP 무결성, 목차, 세 장 포함, 초안 머리말 제거 확인
- 웹: 세 장의 목차와 본문, v0.3 저장 키, 외부 의존성 없는 단일 HTML 확인
- PDF: 19쪽, 한글 부분 글꼴 포함, 메타데이터·책갈피·본문 추출 확인
- PDF 전 페이지 렌더링에서 글자 누락, 겹침, 잘림과 깨진 글리프가 없음을 확인

## 사용자 교정에서 확인할 부분

- 제2장의 MVP 예시가 너무 제품 개발에 치우쳐 보이지 않는가?
- “친절”이 LLM의 성격 묘사로 읽히지 않고 응답이 확장되는 방식으로 이해되는가?
- 제3장의 되말하기 문장이 실제 대화에서 사용할 만큼 짧고 자연스러운가?
- 1부를 다 읽은 뒤 독자가 세 장의 차이와 연결을 자기 말로 설명할 수 있는가?

현재 결과는 출간 승인본이 아니라 **1부 전체를 이어 읽으며 직접 교정하기 위한 v0.3 원고**다.
