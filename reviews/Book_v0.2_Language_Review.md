# Book v0.2 Language Review

> Status: `COMPLETE / READY FOR USER CORRECTION`
> Date: 2026-09-30
> Scope: 제목·부제·제1장·목차·세 판본의 안내 문구

## 검토 목적

《첫 답은 끝이 아니다》가 LLM의 첫 응답만 가리키는 것처럼 읽히는 문제를 바로잡고, 첫 프롬프트에서 시작해 초기 대화를 거쳐 만들어진 첫 MVP를 완성으로 오해하지 말자는 뜻이 책 전체에서 일관되게 드러나는지 확인했다.

## 적용한 표현 기준

1. `첫 답`은 인용이나 특정 응답을 뜻할 때만 사용하고, 중심 개념은 `첫 결과물`로 통일한다.
2. `첫 결과물`은 문서·코드·디자인·계획·MVP를 포함한다고 처음에 정의한다.
3. 빠른 생성 자체를 비판하지 않고, 매끄러운 외형 때문에 판단을 멈추는 태도를 문제로 삼는다.
4. `끝`처럼 대상이 모호한 표현보다 `검증`, `완료 판단`, `한 단계 마무리`를 사용한다.
5. 수정은 실패나 뒷수습이 아니라 목표·경계·완료 조건을 맞추는 본 작업으로 설명한다.
6. LLM만 평가하지 않고 사용자도 결과물을 보며 자신의 기준을 발견한다는 상호성을 유지한다.
7. 실제 대화를 다듬어 인용할 때는 원문의 의미를 유지했다는 편집 경계를 표시한다.

## 주요 변경

| 이전 | v0.2 | 이유 |
|---|---|---|
| 첫 답은 끝이 아니다 | 첫 결과물이 곧 완성은 아니다 | 첫 MVP까지 포함하고 완료 착각을 직접 지적 |
| 인간과 LLM이 서로의 뜻을 맞춰 가는 대화의 기술 | 첫 프롬프트와 MVP 이후, 인간과 LLM이 함께 완성해 가는 법 | 책의 출발점과 독자가 얻게 될 행동을 구체화 |
| 첫 답은 왜 끝처럼 보이는가 | 완성처럼 보이는 첫 결과물 | ‘답’과 ‘끝’의 모호함 제거 |
| MVP는 작은 완성품이 아니다 | MVP는 완료 선언이 아니라 검증의 시작이다 | MVP의 역할을 긍정문으로 설명 |
| 좋은 첫 답보다 좋은 두 번째 질문 | 더 좋은 결과물보다 더 정확한 다음 질문 | 순서보다 정확한 의미 확인을 강조 |
| 결과를 만들어내는 건 인스턴트적 사고라는 점은… | 내가 말한 인스턴트적 사고란…여기는 생각이다 | 겹치는 명사형과 설명형 어미를 정리하고 편집 인용임을 표시 |
| 결과물은 더 좋아 보일 수 있지만 목표에서는 멀어질 수 있다 | 일반적인 완성도와 사용자의 목표 적합성이 다른 이유를 안내문·MVP 사례로 설명 | 결론만 제시하던 문장을 독자가 검증할 수 있는 설명으로 보강 |

## 검증 결과

- 제목·부제·목차·제1장·웹·EPUB·PDF의 중심 용어가 일치한다.
- 제1장 첫 부분에서 ‘첫 결과물’의 범위를 명시했다.
- 웹 교정본은 v0.2 전용 저장 키를 사용해 v0.1 교정 내용과 충돌하지 않는다.
- EPUB 구조 검사와 웹 정적 검사를 통과했다.
- PDF는 v0.2 전체 문자를 포함하도록 부분 글꼴을 다시 만들었고, 8쪽을 렌더링해 글자 누락·잘림·겹침이 없음을 확인했다.

## 사용자 교정에서 확인할 부분

- `첫 결과물`의 정의가 너무 설명적이거나 반복적으로 느껴지는가?
- ‘문제 제기자’, ‘완료 조건’, ‘경계’ 같은 ORBIT 용어가 일반 독자에게 어렵지 않은가?
